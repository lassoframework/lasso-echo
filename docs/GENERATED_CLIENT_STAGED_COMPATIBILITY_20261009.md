## Selected architecture

Astra rejected the exploratory direct ACTIVE-row route. Its RPC now always
rejects. The additive staged adapter follows the existing forward contract.

1. The isolated owner reads an exact plan for a NEW deterministic candidate UUID
   replacing the existing active pending null-image gap placeholder. Full old
   calendar and bound gap-request snapshots are frozen, including account/format.
2. The existing SQLite generation journal freezes candidate, new row UUID,
   artifact version UUID, complete stage plan and original manifest BLOB before
   issuance. Receipt UUID attachment is immutable. Missing receipt holds.
3. A newly opened dedicated reader performs the committed authority lookup.
   Caller dictionaries and standalone version rows supply no authority. The
   producer receives no issuer credential.
4. The owner preparation RPC rechecks receipt, current source/brand, complete
   fresh photo exhaustion and original/derivative history, reserves permanent
   generated identity, then persists restricted preparation. It does not insert
   or activate a calendar row. Uncertain commit reconciles exact durable evidence.
5. The normal service stage RPC consumes exactly the returned full planned row,
   with final URLs, generated marker, version and SHA already present. It inserts
   an inactive pending candidate with `forward_reservation_staged`, and stores
   the exact complete old-placeholder CAS snapshot. No approval stamp is created.
6. The actual separate service finalizer worker calls the same public finalizer
   signature. Generated singleton batches must match preparation, committed
   receipt, batch membership and full placeholder/gap CAS. A private transaction
   decision permits activation only inside that finalizer transaction. Exact gap
   rebind occurs before the unchanged original finalizer so the existing gap-slot
   guard sees the inactive candidate. Any failure rolls back rebind, activation,
   reservation, archive and receipt together. Ordinary batches delegate unchanged.
7. Only after persisted terminal finalization may the actual portal client-owner
   path approve the exact displayed snapshot and stamp the authenticated human.
   Coach/staff/autonomy/revoked/stale/edited paths continue to hold.

Generic drafter/mirror generated holds and the existing provider/claim guards
remain unchanged. Reader injection is explicit; CLI/environment provisioning is
